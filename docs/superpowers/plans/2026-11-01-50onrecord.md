# 50onrecord Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pagina Instagram "50onrecord" che ricerca, scrive, impagina in stile fanzine e pubblica da sola caroselli di storie musicali 1960–2010, usando solo l'abbonamento Claude dell'utente e servizi gratuiti.

**Architecture:** Due metà separate. (1) **Generazione** — una routine Claude Code nel cloud (abbonamento) fa ricerca e scrittura e produce un file `story.json` per carosello, che pusha su un branch `claude/…`. (2) **Cancello e pubblicazione** — GitHub Actions (gratuite su repo pubblico) valida ogni `story.json` con regole deterministiche, scarica le foto con licenza verificata, genera le slide con Playwright, mette il carosello in coda su `main` e, agli orari previsti, lo pubblica tramite l'API di Instagram usando URL `raw.githubusercontent.com` pubblici. Le regole su fatti, foto e testi sono imposte dal codice del cancello, non dalla buona volontà del modello.

**Tech Stack:** Python 3.12, pydantic 2, Jinja2, Playwright (Chromium), requests, pytest, responses; GitHub Actions; routine Claude Code; Instagram API with Instagram Login (content publishing); Wikimedia Commons API.

**Spec:** `docs/2026-11-01-50onrecord-design.md`

## Global Constraints

- Repository nuovo e **pubblico** `50onrecord`, completamente separato da Quick Pastry (nessun file di `QP` viene toccato).
- Budget: solo abbonamento Claude; nessuna API a pagamento, nessun servizio a pagamento.
- Slide 1080×1350 PNG; carosello da 6 a 8 slide (limite tecnico API: 10).
- Testi in italiano. Nessuna dicitura "da verificare", "si dice", "pare che", "sembra che", "forse", "secondo alcuni" su slide o didascalia.
- Ogni fatto: almeno **2 fonti indipendenti** (domini diversi, mirror di Wikipedia contano come Wikipedia).
- Citazioni di testi di canzoni: al massimo **5 parole** tra virgolette.
- Licenze foto ammesse: Public domain, CC0, CC BY *, CC BY-SA *. Escluse: qualsiasi NC o ND, "fair use", sconosciuta. Mai immagini generate con IA di artisti reali.
- Orari Europe/Rome: fase 1 (prime 8 settimane da `start_date`) 12:30 e 20:30; fase 2 solo 20:30. Se in coda ci sono meno di 2 caroselli pronti, si pubblica solo lo slot delle 20:30.
- Hashtag: al massimo 5. Didascalia: crediti foto (autore + licenza + link), fonti, nota "slide rilasciate CC BY-SA" quando una foto è BY-SA, chiusura fissa.
- Circa 1 carosello su 10 su artisti italiani; mai due caroselli consecutivi con stesso artista o stesso decennio.
- Segreti (token Instagram, PAT GitHub) solo come GitHub Secrets, mai nel repo.
- Avvisi: un workflow GitHub **fallisce** (e GitHub manda email al proprietario) quando: 2 slot saltati di fila, coda vuota, token in scadenza entro 7 giorni, pubblicazione rifiutata da Meta.

## Review Focus

- **Cambio ora legale/solare** (ultima domenica di marzo/ottobre): lo slot delle 12:30 deve uscire alle 12:30 di Roma, non un'ora prima o dopo → test in Task 7.
- **Mirror di Wikipedia contati come fonti diverse** (wikiwand, fandom-mirror, ipfs): il validatore li deve trattare come lo stesso dominio → test in Task 2.
- **Parole lunghe e accenti** ("Düsseldorf", "psichedelico", titoli di 30+ caratteri) che escono dai ritagli o dalle slide → test di overflow in Task 5.
- **Artista senza foto libere**: il carosello deve uscire comunque nella variante senza foto, non fallire → test in Task 4 e Task 5.
- **Container Instagram non pronto** (`status_code` IN_PROGRESS) o URL immagine rifiutato: il publisher deve attendere/ritentare e, se fallisce, lasciare il carosello in coda e far fallire il workflow → test in Task 8.

### Task 10: Skill di generazione per la routine

**Files:** Create `.claude/skills/genera-carosello/SKILL.md`, `incoming/.gitkeep`

The routine prompt is: *"Usa la skill genera-carosello per preparare 2 caroselli."* The skill tells Claude, in Italian:
1. `git pull`; run `python -m onrecord constraints` and respect its output.
2. Pick a story (1960–2010) per spec §5 that is not a duplicate; prefer stories with free photos on Commons (check with a quick search).
3. Research: collect facts; every fact needs ≥2 independent sources (spec §6); private life only if documented; no invented colour details; lyrics only paraphrased, ≤5 quoted words.
4. Write `incoming/<id>/story.json` following `onrecord/models.py` (6–8 slides; slide structure spec §5; `source_note` on the slide whose main fact is an artist statement).
5. Run `python -m onrecord build incoming/<id> --no-render` (validation + photo resolution only, since rendering runs in the gate) and fix or discard the story until it passes; after 3 failed attempts on one story, discard it and pick another.
6. Commit `incoming/` only and push to `claude/carosello-<date>`.
